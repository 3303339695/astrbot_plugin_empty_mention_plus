# 空 @ 接话

只把“@机器人”或唤醒词本身交给模型，不塞固定提示词，也不翻上一条旧消息。

## 处理规则

先判断是不是空 @ / 只唤醒，再决定要不要把 @ 本身交给模型：

- **只 @**：默认把“@机器人”本身交给模型；也可以在插件配置里关掉“保留 @”，只给称呼；
- **只发唤醒词**：把唤醒词本身交给模型，正常回一句，然后等六十秒；
- **带内容的唤醒词**：把被框架剪掉的唤醒词补回消息，命令消息除外；
- **带 @ 的正常内容**：照旧去掉 @，不额外处理；
- **等待**：只认刚才那个人，同群别人说话不会被抓走；等到了就接上，等不到就结束。

## 为什么不接上一条

群友可能是先 @ 再发问题，也可能先发问题再 @。如果自动翻上一条，
遇到“先 @ 再发内容”的人，很容易把上一轮聊的旧话题接进来。  
所以只 @ / 只唤醒时，只把 @ 或唤醒词本身交给模型，让模型先回一句；
真正的问题等下一句再处理。

## 安装后要做的

1. 导入安装包；
2. 在“配置文件 → 平台配置 → 基本 → 可用插件”里勾上“空@接话”，保存；
3. 到群里先 @ 一下，看机器人是否回一句，再发问题；
4. 也可以先发一句带唤醒词的话，测试唤醒词有没有被补回。

原来那个“只 @ 机器人是否触发等待”的开关，开不开都行；这个插件会在它前面接管。

## 配置

- 保留 @：只 @ 时模型看到“@称呼”；关掉后只看到“称呼”；
- 称呼兜底：消息里拿不到机器人昵称时用的名字，例如“召唤”；
- 等待秒数：默认六十秒；
- 补回唤醒词：带内容的消息是否补回被剪掉的唤醒词。

## 注意

- 如果导入过旧版本，先在插件页删掉旧的，再导入这个新版。
- 等待期间发指令会作为新消息重新处理，不会被当成接话内容。
- 不要和其他接管空 @ / 唤醒流程的插件一起开，容易叠两层等待。
- 上一条旧消息不会被读取，避免不相关话题混进来。
